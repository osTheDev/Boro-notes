# Boro Notes

- Kotlin + Jetpack Compose + Material 3, Room for storage. Package `com.boro.notes`.
- Layout: width >= 600dp (`TWO_PANE_MIN_WIDTH`) shows list + editor side by side; narrower shows one pane.
- The owner works from a phone only. CI (`.github/workflows/build.yml`) runs tests, builds the APK and publishes it as a GitHub Release; PRs get a `pr-N` prerelease. Keep that flow working.
- The debug keystore in `app/` is committed on purpose so builds install over each other. Don't regenerate it.
- No S Pen: drawing features must work well with a finger (snap-to-grid, auto-straighten).
- Tests: `./gradlew testDebugUnitTest` (ViewModel tests + Robolectric layout tests at cover and inner widths).
- Sketch engine (`sketch/Geometry.kt`) is plain Kotlin: corner detection on a resampled stroke, straight runs vs smooth (Hermite) runs, grid snap on corners only, endpoint magnet. Its tests (`GeometryTest`) can run in a plain Kotlin JVM project without the Android SDK.
- Database is version 8 (v2 designs table, v3 `notes.content`, v4 tasks: `habits`, `habit_checks`, `todos`, v5 `journals`, `journal_pages`, `deletedAt` on notes/designs, v6 `journal_pages.chapter`: a chapter starts at the page that names it, v7 `journals.paper`: the book's page paper as Paper JSON, null = ruled cream, v8 `wishes`: the savings list, price in cents). Every schema change needs a Migration plus a case in `MigrationTest`; users have real notes on their phone.
- Rich notes (`notes/NoteDoc.kt`): `notes.content` holds a JSON block list (text as HTML, checklist, table, columns, divider, image, drawing); `notes.body` keeps plain text for search and list previews. Null content means a legacy plain note. UI in `ui/NoteEditor.kt`; the toolbar is `ui/FormattingBar.kt`: icon tools in colour-coded groups (text, lists, insert, page) plus a second row for the selected block (fill, table rows/columns, move, delete). Paper (colour, lines, margin) lives in the doc JSON.
- Rich text uses `richeditor-compose` pinned at 1.0.0-rc13: newer versions need Kotlin 2.4 / Compose 1.11. Don't bump it without bumping those.
- App opens on Home (`ui/HomeScreen.kt`): stitched tiles per section; "Soon" tiles for future sections (add a `Section` and flip the tile's `section` when one lands). Look settings (theme preset, light/dark, home pattern, tile colours) live in `ui/theme/Theme.kt` and are saved in SharedPreferences, not Room.
- Tasks (`ui/TasksScreen.kt`): weekly punch cards (a habit + one `habit_checks` row per punched day, epoch day), a to-do list and Saving up (`wishes`: name + price, your order or sorted by price, bought ones fold away). No title bar: on the inner screen the status-bar strip shows a summary.
- Media blocks (`ui/MediaBlocks.kt`): photos come from the system photo picker and are copied into `filesDir/images` (JPEG, max 2048 px); the block stores the file name. Drawing blocks store finger strokes (x as a fraction of width, y in dp) plus canvas colour and guide pattern. Placed drawings are locked (never draw while scrolling); drawing happens in a full-screen paint overlay (`ui/DrawingOverlay.kt`, DocEditor `sketching`) whose canvas matches the page width, opened by Insert drawing or Edit drawing. Empty captions only show while their block is selected.
- Journals (`ui/JournalScreen.kt`, `JournalViewModel`): a shelf of cloth-bound books (colour + sashiko pattern index, editable title). On the cover screen a picked book shows its closed cover until unfolded (or "Open here"); unfolded it opens in book view by default: a two-page spread where both pages are edited in place (VM `spread`, `drafts`, `turnTo`), swipe turns two pages with no animation, and the contents (titles grouped by chapter) open over the left page. Leaving book view shows dated pages beside a NoteEditor. The cover editor sets the book's page paper; changing it repapers pages still on the old paper (pages given their own keep it). Pages use the same NoteDoc JSON.
- Trash (`ui/Trash.kt`): notes, designs, journals and pages are soft-deleted (`deletedAt`) and purged after `TRASH_DAYS` (7) at app start. Deleting always asks first (`ConfirmDeleteDialog`); Trash opens from the Home bin icon.
